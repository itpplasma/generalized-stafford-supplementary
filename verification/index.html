Verification record

The Lean proof is checked by the formal repository's own verifiers. This page records the exact pins, the checksum of the challenge file that states the compared theorems, and the verifier commands and results as the formal repository records them. Machine checks establish that the Lean proofs prove the Lean statements; whether those statements say what the paper says is a separate question, and neither is human review.

The log is .lake/verification/comparator.log (untracked).

Sandbox. Landrun ran with --best-effort, which Comparator always passes. The kernel offered Landlock ABI v7, below the v9 that Landrun requests, so Landrun enforced filesystem restrictions only: a probe showed unlisted paths unreadable and unwritable, while the network and scope rules of the V9 profile were not applied. A strict run without --best-effort fails at sandbox setup. A second run through a logging shim confirmed that the sandboxed steps (lake builds and lean4export) went through scripts/landrun-wrapper.sh. No unsandboxed diagnostic run was needed.

Tool path. Palomar's About page says that records verified with a Lean toolchain's own lake comparator cite the toolchain commit and bundled-tool digests, and that only earlier records cite standalone Comparator, lean4export and Landrun revisions. This run used the standalone tools. The toolchain's lake comparator was tried once and stopped because bwrap is not installed; it was not installed. The Palomar pages state no required tool version. The registry entry pages are rendered by JavaScript, so no registered entry was inspected.
